# Integrations: what's needed to go live

None of these are connected in the template. Each one has a screen (Admin → Payment Gateways,
Notifications, Integrations & API) and should be built behind an adapter interface with a **sandbox/mock
adapter** for local development and staging.

| Service | Used for | You need | Notes |
|---|---|---|---|
| **bKash** (Tokenized Checkout) | Online payments, refunds | Merchant account, App Key, App Secret, Username, Password | Sandbox credentials from bKash PGW team; refund API requires approval |
| **Nagad** (Merchant API) | Online payments | Merchant ID, merchant private key, Nagad public key | Callback must verify the signed payload |
| **Rocket** (DBBL) | Online payments | Merchant ID, API key | Often via an aggregator instead |
| **SSLCommerz** | Cards, MFS, net banking | Store ID, Store password | IPN (webhook) + validation API; supports refunds |
| **AamarPay** | Hosted checkout | Store ID, Signature key | Alternative aggregator |
| Bank transfer / cash | Manual | Bank account details | Manual verification flow in Admin → Payments |
| **SMS** (e.g. SSL Wireless, Alpha SMS, BulkSMSBD) | OTP, confirmations, reminders | API token, approved **masking sender ID** | Unicode (Bangla) SMS uses more segments, so track cost |
| **WhatsApp** (Meta Cloud API or a BSP) | Confirmations, reminders, campaigns | Business verification, phone number ID, access token, **pre-approved templates** (EN + BN) | Marketing templates need opt-in consent |
| **Email** (Amazon SES / SMTP) | Invoices, receipts | Verified domain (SPF, DKIM, DMARC), credentials | |
| **Web push** | Reminders | VAPID key pair | Generated by the backend |
| **Google Maps** | Maps, directions | API key restricted by HTTP referrer | Static embed works without a key |
| **Google Analytics 4 / Meta Pixel** | Tracking | Measurement ID / Pixel ID | Load only after cookie consent; `dataLayer` events already fire for phone/WhatsApp clicks |
| **Google Login** (optional) | Customer sign-in | OAuth client ID & secret | OTP remains the primary method |
| **Weather API** | Weather board | API key (e.g. OpenWeather, Tomorrow.io) | Advisory only: never auto-cancels unless the rule is enabled |
| **Object storage + CDN** | Photos, receipts, documents | Bucket, access keys, CDN domain | |
| **Error & uptime monitoring** | Reliability | Sentry DSN, uptime monitor | |

## Rules for every gateway adapter

1. Hosted checkout or redirect only. **Never collect or store card numbers or PINs.**
2. Create a `payment_attempt` with an idempotency key before redirecting.
3. Treat the redirect/callback as a hint. Confirm only after **server-to-server verification** or a signed webhook.
4. Store webhooks raw (secrets redacted) with a unique `(gateway, reference, event)` key, and process them from a queue with retries and backoff.
5. Record the gateway fee, so net amounts reconcile with settlement reports.
6. Keep sandbox and live credentials separate per environment. Switching to live requires owner 2FA (see Payment Gateways screen).
